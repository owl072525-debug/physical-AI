# 과제 보고서: 제로샷·비전 모델 6종의 기능, 사용 예시, 비교

작성일: 2026-10-12
대상 모델: YOLOE, DINO-X, SAM 3, SigLIP 2, OCR(EasyOCR), MediaPipe

## 1. 개요

사진이나 영상에서 정보를 뽑는 도구는 "무엇을 얻고 싶은가"에 따라 갈린다. 위치(박스), 모양(마스크), 의미(유사도), 글자(텍스트), 사람의 몸짓(랜드마크)이 서로 다른 모델의 출력이다. 여섯 모델의 한 줄 요약은 아래와 같다.

| 모델 | 한 줄 요약 | 얻는 것 |
|---|---|---|
| YOLOE | 말로 찾을 대상을 정하는 실시간 검출·분할 모델 | 박스, 마스크, 신뢰도 |
| DINO-X | 정확도가 가장 높은 오픈월드 검출 모델(클라우드 API) | 박스, 마스크, 키포인트, 캡션 |
| SAM 3 | 개념 하나로 그 개념의 모든 대상을 분할·추적하는 모델 | 인스턴스별 마스크 |
| SigLIP 2 | 이미지와 문장을 같은 공간의 벡터로 바꾸는 모델 | 벡터, 유사도 점수 |
| OCR(EasyOCR) | 사진 속 글자를 읽는 모델 | 글자 영역 박스, 텍스트, 신뢰도 |
| MediaPipe | 손·몸·제스처를 실시간으로 읽는 온디바이스 도구 | 손 21점, 몸 33점, 제스처 이름 |

## 2. 모델별 기능과 사용 예시

### 2-1. YOLOE

**무엇인가**
Ultralytics가 제공하는 open-vocabulary(어휘 제한 없는) 실시간 검출·인스턴스 분할 모델이다. 이름은 "Real-Time Seeing Anything"에서 왔다. 기존 YOLO는 학습할 때 정한 80개 클래스만 찾지만, YOLOE는 찾을 대상을 추론할 때 말로 정한다.

**주요 기능**
- 텍스트 프롬프트: `set_classes`로 `person`, `hard hat`처럼 글자를 클래스로 지정한다. 재학습이 필요 없다.
- 비주얼 프롬프트: 예시 이미지의 박스를 보여 주고 "이런 것을 찾아라"라고 지정한다. 말로 설명하기 어려운 부품이나 로고에 쓴다.
- 프롬프트 프리: 아무것도 지정하지 않으면 내장 어휘(약 4,585개)에서 알아서 찾는다.
- 모든 검출에 0~1 신뢰도가 붙고, 임계값(예: 0.50) 미만은 버린다.
- 속도: 논문 기준으로 YOLOE-v8s는 YOLO-Worldv2-S보다 LVIS 정확도가 3.5 AP 높고 추론이 1.4배 빠르다.

**사용 예시**
- 현장 사진에서 `person`, `hard hat`을 지정해 안전모를 쓴 사람을 찾는다. 같은 사진에서 지정 단어만 `traffic cone`으로 바꾸면 검출 대상이 통째로 바뀐다.
- 신뢰도 0.50 이상만 남기도록 규칙을 정해 오탐을 줄인다.

**한계**
학습 데이터로 직접 학습한 모델보다 정확도가 낮다. 희귀 클래스와 "손상된" 같은 상태·관계 표현에 약하다. 지정하는 단어 수가 늘수록 추론이 느려진다.

### 2-2. DINO-X

**무엇인가**
Visincept가 제공하는 오픈월드 검출·이해 모델이다. 교재는 "최고 정확도 옵션"으로 소개한다. 직접 설치해 쓰는 방식보다 클라우드 API와 웹 플랫폼으로 접근한다.

**주요 기능**
- 오픈월드 객체 검출: 학습하지 않은 물체도 개념으로 찾는다.
- 세밀한 객체 이해, 분할, 키포인트 검출, 캡션, OCR까지 한 모델군에서 다룬다.
- 파생 모델: DINO-X Video(영상 이해, 보안·리테일), DINO-X Grasp(로봇이 물체를 3D로 인식해 집는 용도).

**사용 예시**
- 제로샷으로 만든 시제품의 정확도를 가장 높은 기준으로 검증할 때 쓴다(교재 114쪽).
- 영상 속 사건을 이해하는 보안 카메라, 로봇 팔의 물체 파지 같은 분야에 쓰인다.

**한계**
클라우드 API 방식이라 인터넷 연결이 필요하고, 호출마다 지연과 비용이 생길 수 있다. 오프라인 환경이나 실시간 임베디드 제어에는 맞지 않는다. 요금 체계는 확인하지 못했다.

### 2-3. SAM 3

**무엇인가**
Meta의 Segment Anything with Concepts. "Promptable Concept Segmentation(PCS)"이라는 방식으로, 개념 하나를 지정하면 그 개념에 해당하는 **모든 대상**을 분할하고 영상에서 추적한다. SAM 2가 점이나 박스로 대상 하나를 고르던 것과 달리, 'penguin' 한 단어로 화면 속 펭귄을 전부 각각의 마스크로 만든다.

**주요 기능**
- 프롬프트: 텍스트(짧은 명사구), 이미지 예시 박스(긍정·부정), 또는 둘의 조합. 점·박스·마스크로 한 대상만 분할하는 SAM 2 방식도 지원한다.
- 출력: 인스턴스마다 고유 ID가 붙은 정밀 마스크.
- 영상 추적: 프레임이 바뀌어도 같은 대상을 따라간다.

**사용 예시**
- 사진 속 특정 사물을 전부 마스크로 따서 면적을 재거나 배경을 제거한다.
- 영상에서 "yellow school bus" 같은 개념을 지정해 해당 차량을 모두 추적한다.

**한계**
가중치(`sam3.pt`)가 자동으로 내려받아지지 않고, Hugging Face에서 접근 권한을 신청해야 한다. 모델 크기가 약 3.45GB이고 공식 속도 측정은 고성능 GPU에서 이뤄졌다. 교재 실습에서도 가중치가 없으면 공식 문서 캡처로 대체했다.

### 2-4. SigLIP 2

**무엇인가**
이미지 인코더와 텍스트 인코더가 같은 공간으로 투영하는 모델이다. 이미지와 문장을 같은 길이의 벡터로 바꿔서, 서로 다른 형태의 데이터를 **코사인 유사도 숫자 하나**로 비교할 수 있다. 시그모이드 손실로 학습해 검색 성능이 높다.

**주요 기능**
- 임베딩: 이미지와 문장을 고정 길이 벡터로 변환한다.
- 제로샷 분류: 후보 문장들을 클래스로 삼아, 사진과 가장 유사한 문장을 고른다. 라벨 학습이 필요 없다.
- 유사도 검색: 문장으로 사진을 찾고, 사진으로 비슷한 사진을 찾는다. 임베딩을 한 번 계산해 두면 된다.

**사용 예시**
- 이번 수업 실습: 고양이 사진 1장과 문장 4개를 비교했다. 코사인 유사도는 "cats sleeping on a couch" +0.1564, "a photo of two cats" +0.1286, "a photo of a dog" +0.0259, "a photo of a car" -0.0079였고, 시그모이드 확률은 "cats sleeping on a couch"가 0.7014로 가장 높았다. 가장 알맞은 문장이 최상위로 나왔다.
- 실무에서는 임베딩을 pgvector나 Weaviate 같은 벡터 저장소에 넣어 이미지 검색 엔진, 중복 이미지 탐지, 도면·문서 검색(RAG)의 시각 축으로 쓴다.

**한계**
출력이 벡터와 점수라서 물체의 위치나 개수는 알려 주지 않는다. 유사도 값 자체는 작게 나오므로(맞는 문장도 0.1~0.2 수준) 절대값보다 순위로 판단해야 한다.

### 2-5. OCR (EasyOCR)

**무엇인가**
사진 속 글자를 위치와 문자열로 뽑아내는 사전학습 모델이다. `readtext` 한 줄이면 (글자 영역 박스, 텍스트, 신뢰도) 목록이 나오며 파인튜닝이 필요 없다.

**주요 기능**
- 글자 영역을 사각형 좌표로 찾는다.
- 인식한 글자를 문자열로 돌려준다.
- 글자마다 0~1 신뢰도를 주어, 애매한 결과를 걸러낼 수 있다.

**사용 예시**
- 교재 실습: 번화가 사진에서 신뢰도 0.30 이상인 글자 영역 6개를 읽었다. "Bar" 1.00, "THE IRISH PUB" 0.99, "&Restaurant" 0.96, "RESTAURANT" 0.68이었고 흐릿한 "C"는 0.39였다. 신뢰도가 확신 정도를 알려 준다.
- 이번 수업에서는 EasyOCR와 RapidOCR(PP-OCR) 두 OCR 모델을 같은 이미지로 비교하는 실습도 진행했다.
- 간판, 영수증, 표지판, 문서의 글자를 데이터로 바꿀 때 쓴다.

**한계**
글자만 읽고 사진의 의미는 이해하지 못한다. 작거나 흐린 글자는 신뢰도가 낮아진다.

### 2-6. MediaPipe

**무엇인가**
Google AI Edge의 온디바이스 비전 도구다. 서버 없이 CPU나 GPU에서 실시간으로 추론한다. 용도별 `.task` 모델 파일을 받아 Tasks API로 쓰며, 결과는 0~1로 정규화된 좌표로 나온다.

**주요 기능**
- Hand Landmarker: 손마다 21개 점(손목 0번, 손가락 끝 4·8·12·16·20번)을 찾고, 최대 2손을 동시에 검출한다. 왼손·오른손도 판별한다.
- Pose Landmarker: 전신 33개 점을 찾는다. 가려진 정도를 visibility로 알려 준다.
- Gesture Recognizer: 좌표 대신 "제스처 이름과 점수"를 준다(Victory, Thumb_Up, Open_Palm 등).

**사용 예시**
- 제스처를 제어 신호로 쓴다. Victory(V)면 사진 촬영, Open_Palm이면 정지처럼 `if` 한 줄로 행동에 연결한다(교재에서 Victory 0.91 → 촬영 트리거 표시).
- 손가락 세기: 학습된 분류기 없이 좌표 규칙만 쓴다. 네 손가락은 끝이 관절보다 위에 있으면 펴진 것, 엄지는 손목에서 더 멀면 펴진 것으로 센다. V 모양이면 2로 센다.

**한계**
사람의 손·몸·제스처 전용이어서 일반 물체는 인식하지 못한다. 손이 가려지거나 조명이 나쁘면 정확도가 떨어진다.

### 3-3. 상황별 선택

| 하고 싶은 일 | 알맞은 모델 | 이유 |
|---|---|---|
| 정해진 물체를 빠르게 찾고 개수를 센다 | YOLOE | 말로 지정하고 실시간으로 동작한다 |
| 정확도가 가장 중요한 검증 | DINO-X | 최고 정확도 옵션이다 |
| 물체의 정확한 모양(마스크)이 필요하다 | SAM 3 | 개념으로 모든 인스턴스를 분할한다 |
| 사진을 문장으로 검색하거나 분류한다 | SigLIP 2 | 같은 공간의 벡터라 유사도로 비교한다 |
| 간판·서류의 글자를 읽는다 | OCR | 글자와 신뢰도를 뽑는다 |
| 손동작·자세로 기기를 조작한다 | MediaPipe | 가볍고 온디바이스로 실시간 동작한다 |

교재도 "빠른 검색·태깅은 SigLIP 2, 문서·간판은 OCR, 정밀 마스크·추적은 SAM 3, 사람이 읽을 설명은 VLM이며, 파이프라인에서는 함께 엮는다"고 정리한다. 예를 들어 YOLOE로 대상의 위치를 찾고, SAM 3로 정밀 마스크를 얻고, OCR로 그 안의 글자를 읽는 식으로 조합할 수 있다.

## 4. 결론

1. 여섯 모델은 서로 경쟁하는 관계가 아니라 **얻고 싶은 정보가 다른 도구**다. 위치는 YOLOE·DINO-X, 모양은 SAM 3, 의미 비교는 SigLIP 2, 글자는 OCR, 사람의 몸짓은 MediaPipe가 맡는다.
2. 대부분 별도 학습 없이 바로 쓸 수 있다. 먼저 제로샷으로 빠르게 시도하고, 정확도나 희귀 클래스가 부족하면 그때 직접 학습(커스텀 학습)으로 넘어가는 것이 교재의 원칙이다.
3. 도구를 고를 때는 정확도뿐 아니라 **실행 환경**(클라우드 의존 여부, GPU 필요 여부, 접근 권한)을 함께 따져야 한다.

## 5. 한계와 참고

- 이 보고서의 SAM 3, DINO-X 설명은 교재와 공식 문서를 근거로 한 것이며, 직접 실행해 비교한 결과는 아니다(SAM 3는 가중치 접근 문제로 교재 실습에서도 문서로 대체).
- 모델 간 속도·정확도 수치는 공식 문서와 논문이 밝힌 값이며, 같은 사진으로 직접 측정한 값이 아니다.
