# OccuFan MCU·SBC 선정 보고서

## 1. 요구 조건

| 구분 | MCU | SBC |
|---|---|---|
| 맡는 일 | 단계 지령 수신(Wi-Fi MQTT), 팬 PWM 출력, CO₂ 센서(I2C) 읽기, 안전 판단(지령이 없으면 100 % 복귀) | 카메라 영상 수신, YOLO26n 사람 검출, 인원 계산·단계 결정, MQTT 브로커, 컨테이너 운영 |
| 전원 | 상시 전원 | 상시 전원 |
| OS | 불필요(켜자마자 동작) | 리눅스·도커 필요 |
| AI | 없음 | 가벼운 비전 AI (5 FPS 이상, CPU 추론) |
| 무선 | Wi-Fi 필수 | Wi-Fi 또는 이더넷 |
| 실시간성 | 보통 (PWM, 지령 타임아웃 감시) | 낮음 (2초 중앙값으로 처리) |

## 2. MCU 후보 비교

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **ESP32-S3** | Wi-Fi+BLE, 듀얼코어 240 MHz, 자료·예제 풍부, AI 벡터 명령 | 단순 센서용으로는 과함, C3보다 가격·전력 높음 | **선정** |
| ESP32 | Wi-Fi+BLE+BT, 가격 대비 성능, 자료 최다 | 이 용도에선 S3와 큰 차이 없음 | 대안 |
| ESP32-C3 | 최저가 Wi-Fi 칩 | 싱글코어 160 MHz라 여유가 적음 | 대안 |
| STM32 | 모터 정밀 제어, 산업용 신뢰성 | 기본형은 무선 없음, 초기 설정 복잡 | 제품화 단계 후보 |
| Arduino Uno | 자료 많음, 5 V 튼튼함 | RAM 2 KB, 무선 없음, MQTT·JSON 처리 불가 | 제외 |
| Raspberry Pi Pico | PIO, 문서 탄탄 | 무선은 W 모델만 가능, ESP32 대비 이점 적음 | 제외 |

**선정 이유**: Wi-Fi MQTT, PWM, I2C를 모두 충분히 처리하고, 핀과 처리량에 여유가 있어 MCU 1개로 단순하게 유지할 수 있다. 이 용도만 보면 ESP32나 C3로도 충분하므로, S3는 카메라·로컬 AI로 확장할 여지를 위한 선택이다.

## 3. SBC 후보 비교

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **Raspberry Pi 5** | 자료 최다, CSI 카메라·GPIO·USB 3 지원, 리눅스·도커 운영 가능, 가벼운 비전 AI 가능 | NPU 없음, 다중 카메라 실시간 AI는 한계, 전력·발열 | **선정** |
| Pi 5 + AI HAT+ | 기존 Pi 코드 그대로, NPU 13·26 TOPS | 모델을 전용 형식으로 변환해야 함, 부피·전력 증가 | 예비 (FPS 부족 시) |
| Jetson Orin Nano | CUDA GPU, 다중 카메라 인식에 강함 | 가격, 전력 7~25 W, 환경 구성이 번거로움 | 과함 |
| RK3588 보드 | NPU 6 TOPS, 가성비 | 모델 변환(RKNN) 필요, 자료 부족 | 입문 단계에 부담 |
| Pi Zero 2 W | 소형, 저전력 | RAM 512 MB라 컨테이너 여러 개·AI 불가 | 제외 |

**선정 이유**: 카메라 1대에서 초당 5장 정도만 처리하면 되는 가벼운 비전 AI(YOLO26n)이고, 리눅스·도커로 컨테이너 4개를 운영해야 한다. 엔진 비교(Intel i5 노트북, 사진 100장)에서 약 5~7 FPS가 나와 목표(5 FPS 이상)에 근접했다. Pi 5가 PC보다 빠르다는 근거는 없으므로 실기기 측정이 필요하다.

## 4. 최종 구성

Raspberry Pi 5(판단·두뇌) + ESP32-S3(반사신경·안전 판단). Pi가 멈춰도 ESP32-S3가 지령이 없으면 스스로 100 %로 복귀한다.

## 5. 한계와 확인할 것 (가정)
- Pi 5에서의 FPS는 아직 측정하지 못했다. PoC에서 측정하고, 5 FPS에 미달하면 AI HAT+를 검토한다.
- 가격과 재고는 조사하지 않았다. 구매 전 확인이 필요하다.
- 부품 수치는 수업 자료 "피지컬 AI 부품 도감"의 대표값이며, 모델·설정에 따라 다르다.
